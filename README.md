# rook-host

The schema authority and host-side core for [Rook](https://rookide.com):
this repo defines the wire protocols Rook devices speak and the
identity, pairing, and link machinery a host machine runs. It contains
no UI, no cloud, and no agent adapter.

A **host** here is the machine your agents run on — the laptop or
workstation that owns the repositories, terminals, credentials, and
agent sessions. Everything else (a phone, a cloud) is a remote surface
that may *view* a bounded projection of the host and *request* a small
vocabulary of actions. The host decides.

## What lives here

| Package | What it is |
|---|---|
| `proto/rook/edge/v1` | The host ↔ cloud rail: durable commands, journaled events, leases, grants |
| `proto/rook/link/v1` | The device ↔ host rail: pairing, authenticated link, live status, answers, commands *(coming with the link milestone)* |
| `projection` | The bounded snapshot vocabulary every rail speaks: `Status`, `Answer`, `Command`, clamps, the command allowlist, natural keys |
| `edge` | Shared protocol constants |
| `edgesign` | Ed25519 authenticity layer: canonical encodings, envelope signatures, approval grants |
| `edgeclient` | The reference device client for the edge rail |

## Design stance

- **The host is the execution authority.** A remote rail requests;
  the host re-evaluates every request under its own local policy
  before acting. See `docs/adr/0001-cloud-coordinates-ide-decides.md`.
- **Projections are deliberately boring.** States, titles, and pending
  ask text go out; terminal contents, source code, prompts, and
  credentials stay home. The `projection` clamps are the enforcement.
- **Commands are an allowlist, never a shell string.** The vocabulary
  grows by protocol change with review, not by a client sending a new
  string.
- **Transport is not identity, and reachability is not authorization.**
  Identity is cryptographic and durable; every action is checked
  against a capability grant.

## Wire compatibility

Deployed hosts keep speaking old builds indefinitely, so FILE-level
protobuf compatibility is enforced by `buf breaking` in CI — a hard
requirement, not a style preference. Signed encodings (`edgesign`) are
versioned by domain label and pinned by golden tests; a change to what
is signed is a new label, never a silent reinterpretation.

Generated code is committed under `gen/` and regenerated by
`make proto` with plugin versions pinned to `go.mod`.

## Layout note

A future workflow engine may live under `engine/` as a **separate Go
module** — core packages never import it, by construction.
